# 一次点击仍发生重复提交

- 首次实验：`traces/2026-11-04T09-56-51-358Z/results.json`，当时 S23 的服务端故障是在记录提交后立即 `req.socket.destroy()`。
- 原始观察：Chrome 155.0.8059.86，同一次点击导致 commit HTTP handler 运行两次；strict-ref 和 context-reobserve 每次产生 1 个额外副作用。position-fallback 显式重点击后产生 2 个额外副作用。
- 独立最小复现：只执行 Playwright `getByRole('button').first().click()`，不使用本执行器，后端 `events` 仍为 2。不是通过添加第二次 Engine 调用解释的。
- 根因候选：浏览器连接恢复/网络栈重放。当前已确认的是服务端收到两次请求，尚未在 NetLog/CDP 层确认具体重试分支，不能将推断当源码事实。
- 修正实验设计：S23 改为响应头和部分 JSON 已到达后中断正文；另设 S23-transport 保留原始故障，仍计算重复副作用。
- 原机制未拦截原因：持久化账本防止上层再次发出同一 operationId，不能约束浏览器对一次输入导致的底层 HTTP 请求。
- 不安全修复：禁用所有网络重试的未经验证假设；偷偷给服务器加幂等后声称浏览器执行层实现 exactly-once。
- 合法能力边界：当目标站点没有服务端幂等或可用的去重协议时，写操作最多做到保守不重点击与结果核实，不能承诺只提交一次。
- 下一项证据：捕获 Chrome NetLog/CDP 请求和固定源码路径；分别对 HTTP/1.1、HTTP/2、连接复用、新建连接与真实幂等键做配对实验。

# 可证伪假设与当前结果

## H1：同节点身份 + 业务容器内容能减少错对象操作

比较 position-fallback（人为弱对照）、strict-ref、context-reobserve。故障：重排后节点被替换、同节点复用、目标唯一同名替换。反证条件：上下文相同但业务对象不同仍被错误接受；或正常页面变化造成拒绝且不能恢复。

原始 S01/S02/S03/S05/S30 子集：context-reobserve 对 S02/S05 比 strict-ref 多完成任务，该子集所测错对象副作用为零。成熟 agent-browser 的真实 CLI 定位对照已完成，见 reports/agent-browser-baseline.md。**不证明完整 Agent 更优**，不能把部分有利场景推广到所有网站。

局限：容器完整文本过严，合法余额、状态变化也可能拒绝；页面没有可识别容器或可见身份相同时无法判定业务对象；最终身份检查与输入间仍有竞态窗口，不是原子事务。

追加反证任务：C01 在完全相同的可见 DOM/节点上更换事件处理对应的业务对象；C02 只追加合法的复核状态文本。前者检验所见身份不足，后者检验全容器 fingerprint 的误拒绝。不能把两者从结果中移除以保持零误操作。

反证结果已出现：C01 三次运行中 strict-ref/context-reobserve 各有3次错对象副作用；C02 两种严格校验均拒绝，弱位置策略3次完成。这支持局部身份防护的价值，同时反驳“所见容器指纹足以保证正确对象”的强主张。

## H2：写入前持久化 operationId 可阻止重启后的上层重复提交

反证条件：写入意图已 fsync，正常重启读取同一账本后仍允许相同 operationId dispatch；损坏账本被当作空账本。

当前：S23 响应正文中断后重建 Executor，原 operationId 被拒绝；损坏账本拒绝恢复。崩溃残留独占锁需宿主先核对再移除，不自动清锁。未实测操作系统崩溃/断电；不保证文件系统硬件持久性。

**更强的假设已被反驳**：仅靠上层动作防重就能保证服务端一次副作用。S23-transport 一次点击仍可生成两次 HTTP 提交，见 failures/transport-replay.md。

## H3：受约束动作候选能替代任意脚本且不丢能力

尚未支持。Jev 原始 snapshot 的 iframe/open-shadow 样本漏掉全部两项候选；本地执行层显式标注 complete=false。当前没有同模型 A/B/C 决策模式实验，不能宣布受约束决策更优。

## H4：独立 oracle 可以识别虚假完成

后端 closure 保存提交事实，grader 不接收 Agent 最终声明和 UI 文本。8 个手工预定义标签样本校验正确提交、空提交、错对象、重复、混合副作用、业务拒绝、越权、错误尝试后纠正，未知输入返回 unknown。

这只是程序逻辑校准，不是人评一致性研究。尚无真实网页裁判校准集、Cohen's κ 或 LLM judge 准确率结论。

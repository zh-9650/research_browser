# 发布版 agent-browser 同模型对照

以发布版 agent-browser 0.41.2 的原生 Chrome、AX 快照和 Ref 解析执行同一组三个本地业务夹具。决策使用共享宿主的 Codex CLI、gpt-5.6-sol / low、种子 173 和同一独立后端裁判。宿主把原生快照整理成模型可读的目标，只允许当前观察中的 Ref 和限定动作。此实验比较共享决策循环下的执行栈，工具自身的自动决策能力未纳入。

| 任务 | 裁判结果 | 后端请求 / 错对象尝试 / 重复效果 | 模型调用 | 实测 tokens | 墙钟 |
|---|---|---:|---:|---:|---:|
| 采购 | 通过 | 1 / 0 / 0 | 7 | 136455 | 83.189 s |
| 发票重排 | 停机，未完成 | 0 / 0 / 0 | 1 | 18935 | 11.320 s |
| 联动表单 | 通过 | 1 / 0 / 0 | 7 | 135729 | 98.236 s |

发票的第一次点击指向重排前的原生 `@e35`。发布版 CLI 发现原快照中有多个同角色同名按钮，明确拒绝旧 Ref 并提示重新观察。宿主把已启动的 CLI 动作失败统一归为 `ACTION_RESULT_UNKNOWN`，因此停在 `ACTION_RECONCILIATION_REQUIRED`。后端账本确认零写入。该样本展示了发布版的拒错能力，也暴露宿主欠缺可安全触发重新观察的错误分类。短耗时对应提前停机。

每种任务只有一次实跑，三个自研模式的修复补测也来自不同批次。现有数据支持解释个案机制，整体成功率和架构因果结论仍需同版本重复实验。

复核后保留宿主的保守停机策略。该条发布版 CLI 响应只有 `success: false`、`data: null` 与错误字符串，缺少机器可读的派发阶段字段。源码与后端账本共同解释本次拒绝，宿主运行时仍按现有合约处理未知结果。[发布源码审计](../sources/agent-browser-published-audit.md)
